# analytics-bench

Reproducible local micro-benchmarks for in-process analytics on a single
machine. Three independent studies live here, each self-contained with its own
script, methodology, and recorded raw output:

| Directory | Study | Question it answers |
|-----------|-------|---------------------|
| [`duckdb-vs-polars/`](duckdb-vs-polars/) | DuckDB vs Polars | On a 10M-row Parquet file, how do the two engines compare on five representative analytical queries (filtered group-by, high-cardinality top-N, time bucketing, small-dimension join, distinct count) in wall-clock time and peak RSS? |
| [`parquet-codecs/`](parquet-codecs/) | Parquet compression codecs | For the same 10M-row dataset, how do compression codec (none / snappy / zstd-3 / zstd-9 / gzip / lz4), row-group size, and dictionary encoding trade off file size against write and read (full-scan, single-column, predicate-pushdown) speed? |
| [`serialization-formats/`](serialization-formats/) | Serialization formats | For one batch of 1,000,000 nested event records, how do JSON (stdlib, orjson), MessagePack, pickle, Avro, Arrow IPC (plain and zstd) and Parquet compare on serialized size (raw and after zstd-3) and on whole-batch encode / decode time? |

Every number in each study's `results.json` and `results_raw.txt` is the direct
output of running its script on the hardware noted below. No values were
hand-edited or synthesized. Each directory's `METHODOLOGY.md` documents exactly
what was executed.

## Hardware

Both studies were run on the same machine (see each directory's `env.txt` for
the full capture):

- **CPU:** Apple M2 Pro (10 cores: 6 performance + 4 efficiency), arm64
- **Memory:** 32 GiB
- **OS:** macOS 26.5.1 (build 25F80)
- **Package manager:** [uv](https://github.com/astral-sh/uv) 0.9.13

Absolute numbers are machine-specific; treat them as relative comparisons under
one consistent environment, not portable constants. Re-run on your own hardware
to get numbers that apply to your setup.

## Reproduce

Both studies use [uv](https://github.com/astral-sh/uv) to create an isolated
virtual environment. The Parquet-codec study reuses the dataset generated by the
DuckDB-vs-Polars study, so run that one first.

### 1. DuckDB vs Polars

```bash
cd duckdb-vs-polars
uv venv .venv && source .venv/bin/activate
uv pip install duckdb polars pyarrow psutil numpy
python gen_data.py 10000000 data.parquet   # generates data.parquet + dims.parquet
python bench.py | tee results_raw.txt       # writes results.json
```

### 2. Parquet compression codecs

Requires `duckdb-vs-polars/data.parquet` from step 1.

```bash
cd parquet-codecs
uv venv --python 3.13 .venv && source .venv/bin/activate
uv pip install pyarrow duckdb psutil zstandard
python bench_codecs.py 2>&1 | tee results_raw.txt   # writes results.json + data_*.parquet
```

## What is checked in vs generated

The generated Parquet datasets (`*.parquet`) and virtual environments (`.venv/`)
are **not** committed — they are reproduced by the commands above and are listed
in `.gitignore`. What is committed:

- the benchmark and data-generation scripts,
- `METHODOLOGY.md` for each study,
- `env.txt` (captured hardware + package versions),
- `results.json` (machine-readable results) and `results_raw.txt` (full run
  stdout) from the recorded runs.

## Layout

```
duckdb-vs-polars/
  gen_data.py        dataset generator (seeded, deterministic)
  bench.py           orchestrator + per-(engine,query) worker + Arrow interop
  METHODOLOGY.md     exactly what was run
  env.txt            hardware + versions
  gen_data_out.txt   recorded dataset-generation output
  results.json       per-engine/per-query times + peak RSS
  results_raw.txt    full stdout of the recorded run
parquet-codecs/
  bench_codecs.py    codec matrix + row-group + dictionary studies
  METHODOLOGY.md     exactly what was run
  env.txt            hardware + versions
  results.json       all run times + medians + file/column sizes
  results_raw.txt    full stdout of the recorded run
```
