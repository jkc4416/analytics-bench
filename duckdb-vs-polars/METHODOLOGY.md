# DuckDB vs Polars Benchmark — Methodology

This document records exactly what was executed to produce `results.json` and
`results_raw.txt`. Every number in those files came from real command output on
the hardware described below. No values were hand-edited or synthesized.

## Hardware and software

Captured in `env.txt` (via `sw_vers`, `sysctl`, `uv pip list`):

| Item | Value |
|------|-------|
| Machine | Apple M2 Pro (10 cores: 6 performance + 4 efficiency) |
| Memory | 32 GiB (`hw.memsize` = 34359738368 bytes) |
| OS | macOS 26.5.1 (build 25F80) |
| Python | CPython 3.11.14 (uv-managed venv `.venv`) |
| uv | 0.9.13 |
| duckdb | 1.5.4 |
| polars | 1.42.1 (polars-runtime-32 1.42.1) |
| pyarrow | 25.0.0 |
| numpy | 2.4.6 (data generation only) |
| psutil | 7.2.2 (RSS sampling) |

Both engines ran with default threading, which resolved to 10 threads on this
machine (`[duckdb] threads=10`, `[polars] threads=10`, logged in
`results_raw.txt`).

## Dataset

Generated by `gen_data.py` (seed = 20260719) and written to `data.parquet`
(Snappy compression). Recorded in `gen_data_out.txt`:

- Rows: 10,000,000
- File size: 126,976,888 bytes (121.09 MiB)
- Generation time: 2.974 s (numpy array construction; excludes Parquet write)
- Columns:
  - `ts` — `timestamp[us]`, uniformly spread over a 90-day window anchored at
    epoch 1,700,000,000 s (2023-11-14 UTC), unsorted.
  - `user_id` — `int32`, Zipf(1.3) draw modulo 500,000 distinct users (skewed:
    a small number of users dominate).
  - `category` — one of 10 strings, dictionary-encoded in Parquet, drawn from a
    skewed multinomial (weights 18..5).
  - `amount` — `float64`, log-normal(mean=3.0, sigma=1.0), rounded to cents.
  - `flag` — `bool`, ~30% true.

A small dimension table `dims.parquet` (10 rows: `category`, `region`, `tier`)
was generated in the same script for the join query.

## Queries

Five queries, defined with identical intent for both engines. DuckDB runs SQL
over `read_parquet(...)`; Polars uses `scan_parquet(...)` lazy frames collected
with `.collect()`. Each query fully materializes its result (DuckDB
`.fetchall()`, Polars `.collect()`).

| id | label | Definition |
|----|-------|-----------|
| q1 | filtered_groupby | `WHERE flag=true` then group by `category` → `sum`, `count`, `avg` of `amount` |
| q2 | highcard_topn | group by `user_id` (500k groups) → `sum(amount)`, order desc, top 20 |
| q3 | time_bucket | truncate `ts` to day × `category` → `sum`, `count` (910 groups) |
| q4 | join_dims | inner join to `dims` on `category`, group by `region` → `sum`, `count` |
| q5 | scan_count_distinct | full scan → `count(*)`, `count(distinct user_id)` |

Note on q4: in `data.parquet`, `category` is dictionary-encoded and Polars reads
it as `Categorical`, whereas `dims.parquet.category` is plain `String`. Both
join keys are cast to `String` before the join so the keys are comparable; this
mirrors DuckDB, which reads both as `VARCHAR`. The cast cost is included in the
Polars timing.

## Measurement protocol

Implemented in `bench.py`:

- **Process isolation.** The orchestrator launches one fresh Python subprocess
  per `(engine, query)` pair (`python bench.py --worker ENGINE QUERY`). This
  keeps the peak-RSS measurement for one query from being polluted by memory
  another query left resident in the same interpreter.
- **Repeats.** Each query runs 1 warmup + 3 timed runs. Only the 3 timed runs
  are recorded. Reported "median" is the median of those 3 timed runs.
- **Timing.** Wall-clock `time.perf_counter()` around the full materialization
  call, per run.
- **Peak RSS.** A background thread samples `psutil.Process().memory_info().rss`
  every ~2 ms. The tracked peak is re-anchored to current RSS at the start of
  each timed run, so each run's `peak_rss` reflects the resident footprint
  during that run. `gc.collect()` is called before each run.
- **Arrow interop.** In a separate subprocess (`--arrow`), a `flag=true` filter
  result is moved DuckDB → `.arrow()` → `polars.from_arrow`, timing each half
  and the round trip (1 warmup + 3 timed). ~3.0M rows transferred.

## Reproduce

```bash
cd duckdb-vs-polars
uv venv .venv && source .venv/bin/activate
uv pip install duckdb polars pyarrow psutil numpy
python gen_data.py 10000000 data.parquet
python bench.py | tee results_raw.txt
```
